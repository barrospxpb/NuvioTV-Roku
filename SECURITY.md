# Segurança

**Não divulgue segredos em Issues públicas.**

Não envie senhas, tokens de acesso ou atualização, cookies, dados de sessão, QR Codes de autenticação válidos, PINs de perfil, chaves de API privadas, chaves de assinatura, listas IPTV privadas ou dados de usuários ao repositório.

Antes de publicar código, faça uma revisão estática e manual, incluindo arquivos de imagem, scripts, configurações e histórico Git. Se algum segredo for publicado por engano, **revogue e substitua a credencial** no serviço correspondente: remover o arquivo em novo commit não apaga o histórico.

Para vulnerabilidades, procure um contato privado com o mantenedor pelo perfil do projeto, sem incluir o segredo na comunicação pública.
